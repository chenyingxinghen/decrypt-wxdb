## 2. 施工中发现并修复的真实缺陷（超出原清单）

1. **`bridge.py` 损坏请求行会崩服务**：`json.loads` 失败时错误分支引用未赋值的 `req` → `UnboundLocalError`，一条坏行拖垮整个引擎循环。改为 `rid` 预置 `None`，坏行也回结构化错误。**验证**：注入 `THIS IS A CORRUPT LINE` 后引擎照常响应后续请求。
2. **`bridge.py` 依赖父进程设 `PYTHONIOENCODING`**：否则 Windows GBK 控制台写 emoji（🤩）即 `UnicodeEncodeError` 崩溃。改为启动即 `sys.stdout/stdin.reconfigure(utf-8)` 自证其身。**验证**：不设该环境变量也能正常输出含 emoji 的会话/统计。
3. **`build.js` minify 会静默删代码**：注释里的 `/**`（如路径 `py/**`）被块注释正则误当块注释起点，一路吞到下一个 `*/`——曾把 `verifyManifest/selfCheck/hasDebugFlag/antiDebug` 整段删掉。加 `assertValidJs()`（`vm.Script` 语法校验），minify 破坏即**构建显式失败**；并规范注释禁用 `/*`。**验证**：`node --check` + 关键函数存在性断言。
4. **`tests/` 下 7 个测试路径失效**：迁入 `tests/` 后 `require('./src/…')`、`__dirname/dist` 仍按旧根解析，实际全部跑不起来。逐一修正为 `../`；`test_livesync.py` 增加「无密钥优雅跳过」。**验证**：`npm test` 14/14。

## 3. 明确未做项与取舍（需使用者知情）

- **asar 打包 / 深度标识符混淆（B-P2）暂缓**。理由：
  1. 本机 `node_modules` 无 `@electron/asar`、`electron-builder`、`javascript-obfuscator`；
  2. asar 需把 `engine/**`（Python 运行时 + 引擎）设为 `asarUnpack`（Python 无法读入 asar、且要 spawn `python.exe`），改动面大且**无法在无头环境充分 GUI 验证**，贸然引入有损「业务鲁棒性」这一更高优先目标；
  3. 深度混淆器对**主进程**代码有正确性风险，一旦回归破坏得不偿失。
- **权衡结论**：本轮把资源投在**主动防护**（完整性全量校验 + 清单签名绑定 + 源码字节码化 + 真实反调试 + DevTools 封锁 + 单实例 + IPC 最小面）——这正是原报告指出 weflow **最弱**的一环。asar/混淆只是「单文件 + 变量名压缩」的**被动门槛**，可作为后续接入 `electron-builder` 正式打包时一并补齐（届时 asar+unpack 天然成形），不阻断当前发布级安全目标。
