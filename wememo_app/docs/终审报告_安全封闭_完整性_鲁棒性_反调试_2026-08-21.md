## 1. 结论总览

| 维度           | 评级     | 一句话结论                                                                                            |
| ------------ | ------ | ------------------------------------------------------------------------------------------------ |
| A. 安全与封闭性    | **B**  | Electron 安全基线全部正确（sandbox/contextIsolation/CSP/XSS 转义），但有 `--no-sandbox` 发布脚本与 bridge 无白名单两个明显缺口 |
| B. 包体环境完整性   | **C**  | 清单机制真实可用（35/35 哈希通过），但引擎源码明文、清单覆盖面窄、`engine/py/**` 整体失控、无 asar 打包                                |
| C. 业务功能鲁棒性   | **A-** | 实测全链路通过，错误兜底密度高；主要缺口是**无单实例锁**（双开竞态）                                                             |
| D. 反侵入 / 反调试 | **D**  | 设计上有（签名+清单+反调试+蜜罐），实现上空转（antiDebug 无任何判定动作）；当前反侵入强度**弱于 weflow**                                 |

**总体结论：功能层已具备交付形态；安全/封闭/反调试层未达到「正式发布」门槛，且未达成「比 weflow 更强」的目标。** 建议按 §5 优先级整改后出正式包。

### 5.3 对标结论

**weflow 的「强」只是打包混淆带来的天然门槛，其主动反调试基本为零。** 但当前 wememo 连这个天然门槛都没有（无 asar、无混淆、源码明文），同时自研的主动反调试又是空转——**实际反侵入强度低于 weflow**。

要达到「比 weflow 更强」，需同时拿到两样：weflow 的打包混淆天然门槛（asar + 混淆）**且** wememo 设计里已有但未生效的主动检测（DevTools/CDP/计时探测/蜜罐）。

## 6. 整改建议（按优先级）

### P0（阻断发布，必须先做）

1. **移除引擎源码明文**：`build.js` 打包时对全部引擎 .py 用自带 Python 编译为 `.pyc` 并**删除 .py 源码**（保持 bridge.py 保留源码做入口或一并编译，用 `runpy` 引导）；同时删除 `keyextract.py:37` 的 `_KNOWN_MASTER_DEBUG`。风险提示：pyc magic 与解释器强绑定，必须用发布同款 Python 编译（build.js:91-109 已有雏形，只是没删源文件）。
2. **补齐 `engine/py/**` 完整性**：manifest 改为对 `engine/py` 下**关键模块**（cryptography/zstandard 的 `.pyd`/核心 `.py`）登记哈希，或构建时对整目录生成 Merkle 清单；`__pycache__` 在构建后清理，并将「删除 .py 后 pyc 必须与 manifest 一致」纳入 loader 校验。

### P1（高优先，随正式包一起修）

1. **启动脚本去掉 `--no-sandbox`**，并补 `app.commandLine.appendSwitch` 级防护；正式发布走 electron-builder 打包（asar 单文件），安装后不暴露源码目录。
2. **真实反调试落地**（替换 loader.js:48-62 空转块）：
   - 轮询 `webContents.isDevToolsOpened()` / `--remote-debugging-port` 参数 / `process.argv` 含 `--inspect` → 检测到即延迟静默退出（对齐现有"不暴露原因"风格）；
   - 计时探测加**阈值判定**（调试器附加导致 `Date.now()` 间隔显著跳变，连续 N 次超过阈值才触发，避免误杀）；
   - 蜜罐字段加**读取方**（如 loader 退出前校验 `global.__wememo_integrity.mark` 是否被外部改写）。
3. **单实例锁**：`app.requestSingleInstanceLock()`，拿不到锁直接退出（顺带消除双开竞态，同时堵住"第二实例附加调试"通道）。
4. **manifest 校验扩大到全部引擎文件**（至少：全部非 py 目录的引擎文件 + 关键 .pyc），loader 启动时全量或抽样校验，失败静默退出。
5. **IPC 加固**：`ipcMain.handle('bridge')` 增加 `sender` frame 校验（`e.senderFrame === win.webContents.mainFrame`）+ 方法白名单（只放 preload 实际使用的集合），阻断任意 method 直通。

### P2（增强，可下一迭代）

1. **标识符混淆**：引入 `javascript-obfuscator`（或至少变量名替换 + 字符串编码），替换现 `minifyJs`（build.js:37-45），让主进程/preload 不再明文可读。
2. **keyextract 目标进程验证**：attach 前用 `QueryFullProcessImageNameW` + DLL 路径校验（须位于微信安装目录）+ 可选数字签名校验，收窄注入面（keyextract.py:520-525）。
3. **asar 加密可选**（electron-builder 的 asar 不加密，可叠加 `@electron/asar` + 自定义加密壳或 `asarmor` 类方案），把反逆向门槛抬到 weflow 之上。
4. **`engine/_bench_tmp` / `_verify_tmp` 移出源码树**或加入 .gitignore（真实解密库副本不得随仓库流转）。

### P3（打磨）

1. `bridge` 的 `init` 重复调用限制为一次；`pyBuf` 加 1MB 上限保护；补一键回归脚本（`npm test` 聚合现有 test\_*.js + engine/test\_*.py）。
